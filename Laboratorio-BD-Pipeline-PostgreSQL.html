⚙️ Pipeline de Construcción

Secuencia de pasos para construir y validar la base de datos en PostgreSQL, desde el análisis hasta la verificación.

1

Análisis de requisitos y reglas de negocio

Identificar entidades, atributos, cardinalidades y restricciones de unicidad antes de escribir una sola línea de SQL.

2

Modelado Entidad-Relación (ER)

Diseñar el diagrama ER normalizando hasta 3FN: entidades cliente, producto, factura, detalle_factura y sus relaciones.

3

Creación del esquema en PostgreSQL

Crear la base de datos y el esquema dedicado (ventas), separando objetos del esquema público.

4

DDL — Tablas con restricciones

Definir tablas con PK, FK, NOT NULL, UNIQUE y CHECK directamente en la declaración de columnas y a nivel de tabla.

5

Índices de rendimiento

Crear índices sobre columnas de búsqueda frecuente (documento, correo, número de factura, FK de relaciones) para garantizar planes de consulta eficientes.

6

Datos de prueba y validación de constraints

Insertar registros de prueba y verificar que las restricciones de negocio se disparan correctamente ante inserciones inválidas.

7

Consultas de verificación

Ejecutar queries sobre vistas del sistema (pg_indexes, information_schema) para confirmar la estructura desplegada.

🏗️ Esquema y Base de Datos

Script completo de creación de la base de datos, extensiones y esquema dedicado.

-- ══════════════════════════════════════════════════════════════ -- Pipeline PostgreSQL — Sistema de Clientes, Productos y Facturas -- Paso 1: Creación de la base de datos y esquema -- ══════════════════════════════════════════════════════════════ -- Ejecutar como superusuario (ej. postgres) CREATE DATABASE ventas_db WITH ENCODING = 'UTF8' LC_COLLATE = 'es_CO.UTF-8' LC_CTYPE = 'es_CO.UTF-8' TEMPLATE = template0; -- Conectarse a la nueva BD: \c ventas_db -- Extensión para UUIDs (opcional, usamos SERIAL como PK) CREATE EXTENSION IF NOT EXISTS pgcrypto; -- Esquema dedicado para aislar objetos del schema public CREATE SCHEMA IF NOT EXISTS ventas; -- Establecer search_path por defecto en la sesión SET search_path TO ventas, public; -- Configurar search_path permanente en la BD ALTER DATABASE ventas_db SET search_path TO ventas, public;

📊 Definición de Tablas

Tabla: cliente

-- ── TABLA: ventas.cliente ─────────────────────────────────── CREATE TABLE ventas.cliente ( id_cliente SERIAL PRIMARY KEY, tipo_documento VARCHAR(5) NOT NULL CHECK (tipo_documento IN ('CC','CE','TI','PP','NIT')), numero_documento VARCHAR(20) NOT NULL, nombre_completo VARCHAR(150) NOT NULL, direccion VARCHAR(255), correo_electronico VARCHAR(120) NOT NULL UNIQUE, celular VARCHAR(20) NOT NULL UNIQUE, created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(), updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(), -- Regla de negocio: (tipo_documento, numero_documento) juntos son únicos CONSTRAINT uq_cliente_documento UNIQUE (tipo_documento, numero_documento) ); COMMENT ON TABLE ventas.cliente IS 'Clientes del sistema'; COMMENT ON COLUMN ventas.cliente.tipo_documento IS 'CC, CE, TI, PP, NIT'; COMMENT ON COLUMN ventas.cliente.numero_documento IS 'Número del documento según tipo'; COMMENT ON COLUMN ventas.cliente.correo_electronico IS 'Único por cliente'; COMMENT ON COLUMN ventas.cliente.celular IS 'Único por cliente';

Tabla: producto

-- ── TABLA: ventas.producto ────────────────────────────────── CREATE TABLE ventas.producto ( id_producto SERIAL PRIMARY KEY, nombre_producto VARCHAR(150) NOT NULL, precio NUMERIC(12,2) NOT NULL CHECK (precio > 0), cantidad INTEGER NOT NULL DEFAULT 0 CHECK (cantidad >= 0), ubicacion_fisica VARCHAR(100), created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(), updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW() ); COMMENT ON TABLE ventas.producto IS 'Catálogo de productos'; COMMENT ON COLUMN ventas.producto.precio IS 'Precio actual del catálogo (referencia)'; COMMENT ON COLUMN ventas.producto.cantidad IS 'Stock disponible en bodega'; COMMENT ON COLUMN ventas.producto.ubicacion_fisica IS 'Estante o ubicación en almacén';

Tabla: factura

-- ── TABLA: ventas.factura ─────────────────────────────────── CREATE TABLE ventas.factura ( id_factura SERIAL PRIMARY KEY, numero_factura VARCHAR(30) NOT NULL UNIQUE, fecha TIMESTAMPTZ NOT NULL DEFAULT NOW(), -- Subtotal de la factura sin IVA subtotal NUMERIC(14,2) NOT NULL DEFAULT 0.00 CHECK (subtotal >= 0), -- Porcentaje general de IVA aplicado en la factura (ej. 19.00) porcentaje_iva NUMERIC(5,2) NOT NULL DEFAULT 19.00 CHECK (porcentaje_iva >= 0), -- Valor monetario del IVA calculado valor_iva NUMERIC(14,2) NOT NULL DEFAULT 0.00 CHECK (valor_iva >= 0), -- Total = subtotal + valor_iva total NUMERIC(14,2) NOT NULL DEFAULT 0.00 CHECK (total >= 0), -- FK: una factura pertenece obligatoriamente a un cliente id_cliente INTEGER NOT NULL REFERENCES ventas.cliente (id_cliente) ON DELETE RESTRICT ON UPDATE CASCADE, created_at TIMESTAMPTZ NOT NULL DEFAULT NOW() ); COMMENT ON TABLE ventas.factura IS 'Cabecera de facturas de venta'; COMMENT ON COLUMN ventas.factura.numero_factura IS 'Único; ej. FAC-2024-001'; COMMENT ON COLUMN ventas.factura.subtotal IS 'Suma de subtotal_linea de los detalles'; COMMENT ON COLUMN ventas.factura.valor_iva IS 'IVA total de la factura'; COMMENT ON COLUMN ventas.factura.total IS 'subtotal + valor_iva';

Tabla: detalle_factura

-- ── TABLA: ventas.detalle_factura ─────────────────────────── -- Resuelve la relación M:N entre factura y producto. -- Almacena precio, cantidad e IVA al momento de la venta -- (snapshot: inmune a cambios futuros del catálogo). -- ──────────────────────────────────────────────────────────── CREATE TABLE ventas.detalle_factura ( id_detalle SERIAL PRIMARY KEY, id_factura INTEGER NOT NULL REFERENCES ventas.factura (id_factura) ON DELETE CASCADE ON UPDATE CASCADE, id_producto INTEGER NOT NULL REFERENCES ventas.producto (id_producto) ON DELETE RESTRICT ON UPDATE CASCADE, -- Snapshot del precio al momento de facturar precio_unitario NUMERIC(12,2) NOT NULL CHECK (precio_unitario > 0), -- Cantidad de unidades del producto en esta línea cantidad INTEGER NOT NULL CHECK (cantidad > 0), -- Porcentaje de IVA aplicado a este producto al facturar porcentaje_iva NUMERIC(5,2) NOT NULL DEFAULT 19.00 CHECK (porcentaje_iva >= 0), -- subtotal_linea = precio_unitario * cantidad (sin IVA) subtotal_linea NUMERIC(14,2) NOT NULL CHECK (subtotal_linea >= 0), -- Evitar duplicar el mismo producto en la misma factura CONSTRAINT uq_detalle_factura_producto UNIQUE (id_factura, id_producto) ); COMMENT ON TABLE ventas.detalle_factura IS 'Líneas de producto por factura (snapshot)'; COMMENT ON COLUMN ventas.detalle_factura.precio_unitario IS 'Precio del producto al momento de venta'; COMMENT ON COLUMN ventas.detalle_factura.porcentaje_iva IS 'IVA aplicado a este producto al vender'; COMMENT ON COLUMN ventas.detalle_factura.subtotal_linea IS 'precio_unitario * cantidad';

Trigger: actualizar totales de factura

-- ── FUNCIÓN y TRIGGER: recalcular totales en factura ──────── CREATE OR REPLACE FUNCTION ventas.recalcular_factura() RETURNS TRIGGER AS $$ DECLARE v_subtotal NUMERIC(14,2); v_valor_iva NUMERIC(14,2); v_id_fac INTEGER; BEGIN v_id_fac := CASE WHEN TG_OP = 'DELETE' THEN OLD.id_factura ELSE NEW.id_factura END; SELECT COALESCE(SUM(subtotal_linea), 0), COALESCE(SUM(subtotal_linea * porcentaje_iva / 100), 0) INTO v_subtotal, v_valor_iva FROM ventas.detalle_factura WHERE id_factura = v_id_fac; UPDATE ventas.factura SET subtotal = v_subtotal, valor_iva = v_valor_iva, total = v_subtotal + v_valor_iva WHERE id_factura = v_id_fac; RETURN NULL; END; $$ LANGUAGE plpgsql; CREATE TRIGGER trg_recalcular_factura AFTER INSERT OR UPDATE OR DELETE ON ventas.detalle_factura FOR EACH ROW EXECUTE FUNCTION ventas.recalcular_factura();

⚡ Índices

Estrategia de indexación orientada a las consultas más frecuentes del sistema: búsqueda de cliente por documento, correo o celular; consulta de facturas por cliente o número; y joins en detalles de factura.

🔑 PK implícita (B-tree) ✦ UNIQUE (B-tree) ◆ Índice de rendimiento
-- ══════════════════════════════════════════════════════════════ -- ÍNDICES — ventas_db -- Los constraints UNIQUE y PRIMARY KEY ya crean índices B-tree. -- Los siguientes son adicionales para rendimiento en búsquedas. -- ══════════════════════════════════════════════════════════════ -- ── cliente ───────────────────────────────────────────────── -- Búsqueda por correo (login, búsqueda rápida) CREATE INDEX idx_cliente_correo ON ventas.cliente (correo_electronico); -- Búsqueda por celular CREATE INDEX idx_cliente_celular ON ventas.cliente (celular); -- Búsqueda por tipo y número de documento (ya cubre el UNIQUE, -- pero un índice explícito permite consultas por tipo_documento solo) CREATE INDEX idx_cliente_tipo_doc ON ventas.cliente (tipo_documento); -- Búsqueda por nombre (ILIKE %texto%) → GIN+trigram es mejor, -- pero para búsqueda exacta o prefix basta B-tree CREATE INDEX idx_cliente_nombre ON ventas.cliente (nombre_completo); -- ── factura ────────────────────────────────────────────────── -- Facturas de un cliente (JOIN más frecuente) CREATE INDEX idx_factura_cliente ON ventas.factura (id_cliente); -- Rango de fechas (reportes, cierres de mes) CREATE INDEX idx_factura_fecha ON ventas.factura (fecha DESC); -- ── detalle_factura ────────────────────────────────────────── -- Detalles de una factura (el JOIN más intensivo del sistema) CREATE INDEX idx_detalle_factura ON ventas.detalle_factura (id_factura); -- Historial de un producto en facturas CREATE INDEX idx_detalle_producto ON ventas.detalle_factura (id_producto); -- ── Verificación de índices creados ────────────────────────── SELECT schemaname, tablename, indexname, indexdef FROM pg_indexes WHERE schemaname = 'ventas' ORDER BY tablename, indexname;

ventas.cliente

PK id_cliente UQ correo_electronico UQ celular UQ (tipo_doc, num_doc) IDX tipo_documento IDX nombre_completo

ventas.factura

PK id_factura UQ numero_factura FK id_cliente IDX id_cliente IDX fecha DESC

ventas.producto

PK id_producto CHECK precio > 0 CHECK cantidad ≥ 0

ventas.detalle_factura

PK id_detalle FK id_factura FK id_producto UQ (id_factura, id_producto) IDX id_factura IDX id_producto

📋 Reglas de Negocio Implementadas

Todas las reglas se implementan como constraints en DDL, garantizando integridad sin depender de la capa de aplicación.

Unicidad

  • (tipo_documento, numero_documento) — UNIQUE en tabla cliente. Ambos campos juntos son únicos; permite el mismo número con diferentes tipos.
  • correo_electronico — UNIQUE en tabla cliente. Ningún cliente puede registrarse con un correo ya usado.
  • celular — UNIQUE en tabla cliente. Un número de celular identifica unívocamente a un cliente.
  • numero_factura — UNIQUE en tabla factura. Garantiza trazabilidad contable sin duplicados.
  • (id_factura, id_producto) — UNIQUE en detalle_factura. Un producto no se repite en la misma factura; se consolidan cantidades.

Integridad Referencial

  • Una factura debe tener un cliente — FK id_cliente NOT NULL con ON DELETE RESTRICT (no se puede eliminar un cliente con facturas).
  • Un producto puede estar en varias facturas — FK en detalle_factura con ON DELETE RESTRICT en producto (no se elimina un producto si tiene historial de ventas).
  • Una factura puede tener uno o más productos — Cardinalidad 1:N entre factura y detalle_factura; CASCADE en delete.

Consistencia de Datos (CHECK)

  • precio > 0 — Los productos no pueden tener precio cero o negativo.
  • cantidad ≥ 0 — Stock de producto no puede ser negativo.
  • precio_unitario > 0, cantidad > 0 — Líneas de factura con valores positivos.
  • porcentaje_iva ≥ 0 — IVA no puede ser negativo (puede ser 0 para exentos).
  • tipo_documento IN (CC,CE,TI,PP,NIT) — Valores controlados de tipos de documento colombianos.

Snapshot de Precios

  • precio_unitario y porcentaje_iva en detalle_factura — Se almacena el precio e IVA vigente al momento de la venta. Si el catálogo cambia, las facturas históricas no se ven afectadas.

Automatización

  • Trigger trg_recalcular_factura — Recalcula subtotal, valor_iva y total de la cabecera de factura automáticamente tras INSERT / UPDATE / DELETE en detalle_factura.
