DDL — Estructura relacional

⏱ 50 min · 0:30 → 1:20
🎯 Objetivo: El aprendiz comprende por qué existe la tabla intermedia y puede crear las 3 tablas con sus restricciones.
💡 El problema pedagógico central (5 min): Si pusiéramos autor como columna de libros, la Antología del Cuento Colombiano tendría que repetirse 3 veces para sus 3 autores. La tabla intermedia libro_autor resuelve eso.
💻 Código DDL completo
SQL — DDL 
-- ① Crear la base de datos (ejecutar sola, luego reconectar)
CREATE DATABASE biblioteca_medellin;

-- Conectarse a la nueva BD antes de continuar:
-- En pgAdmin: clic derecho → Connect to Database

-- ② Tabla de Autores
CREATE TABLE autores (
    autor_id    SERIAL       PRIMARY KEY,
    nombre      VARCHAR(100) NOT NULL,
    nacionalidad VARCHAR(50)  DEFAULT 'Colombiana'
);

-- ③ Tabla de Libros
CREATE TABLE libros (
    isbn             VARCHAR(20)  PRIMARY KEY,
    titulo           VARCHAR(200) NOT NULL,
    anio_publicacion INTEGER
);

-- ④ Tabla Intermedia — rompe la relación N:M
CREATE TABLE libro_autor (
    isbn     VARCHAR(20)  REFERENCES libros(isbn)   ON DELETE CASCADE,
    autor_id INTEGER      REFERENCES autores(autor_id) ON DELETE CASCADE,
    PRIMARY KEY (isbn, autor_id)
);
✅ Verificación: En el árbol de pgAdmin → biblioteca_medellin → Schemas → public → Tables deben aparecer las 3 tablas. Si no aparecen, clic derecho en Tables → Refresh.
Punto de pausa pedagógica (5 min) Preguntar: "¿Por qué libro_autor no tiene un id propio?" → Porque la combinación (isbn + autor_id) ya es única: un autor no puede repetirse en el mismo libro. Eso se llama clave primaria compuesta.

Consultas y Filtros

⏱ 50 min · 2:10 → 3:00
🎯 Objetivo: El aprendiz filtra datos con confianza usando SELECT, WHERE y los operadores lógicos AND / OR / NOT.
💻 Progresión de consultas (practicar en orden)
1. SELECT básico
-- Ver todos los libros
SELECT * FROM libros;

-- Ver solo dos columnas
SELECT titulo, anio_publicacion FROM libros;
2. WHERE con AND
-- Libros del siglo XXI
SELECT titulo, anio_publicacion
FROM   libros
WHERE  anio_publicacion > 2000;
3. WHERE con NOT LIKE
-- Autores cuyo nombre NO empieza con 'G'
SELECT nombre
FROM   autores
WHERE  nombre NOT LIKE 'G%';
4. WHERE con OR (rango de años)
-- Libros del siglo XIX o anteriores al 1930
SELECT titulo, anio_publicacion
FROM   libros
WHERE  anio_publicacion < 1900
   OR  (anio_publicacion >= 1900 AND anio_publicacion < 1930);
5. BETWEEN (equivalente más legible)
-- Libros publicados entre 1980 y 2010
SELECT titulo, anio_publicacion
FROM   libros
WHERE  anio_publicacion BETWEEN 1980 AND 2010;
Ejercicio de comprobación (10 min) Pedir a los aprendices que escriban ellos solos: "Muéstrame solo los libros publicados después de 1960 que contengan la letra 'a' en el título." — respuesta esperada: WHERE anio_publicacion > 1960 AND titulo LIKE '%a%'

Ordenamiento y Formato

ORDER BY ASC / DESC
-- 5 libros más recientes

FROM   libros
ORDER BY anio_publicacion DESC
LIMIT  5;

FROM   autores
ORDER BY nombre ASC;
Funciones de texto
-- UPPER: nombres en mayúsculas

FROM   autores;

-- LENGTH: longitud del título
SELECT titulo, LENGTH(titulo) AS "Caracteres"
FROM   libros
ORDER BY LENGTH(titulo) DESC;

JOINs — Consultas multitabla

⏱ 40 min · 3:30 → 4:10
🎯 Objetivo: El aprendiz entiende cómo la tabla libro_autor actúa como puente y puede escribir un JOIN a 3 tablas antes del reto.
🗺 Diagrama conceptual de los JOINs
  autores            libro_autor         libros
  ───────            ──────────────      ──────
  autor_id ◄────── autor_id              isbn ◄────── isbn
  nombre             isbn ────────────►           titulo
  nacionalidad                              anio_publicacion

  LEFT ──JOIN──────────────────────────────────►
  (de autores hacia sus libros, pasando por el puente)
💻 JOINs progresivos
JOIN 1 — ¿Quién escribió la Antología?
SELECT l.titulo, a.nombre AS "Autor"
FROM   libros l
JOIN   libro_autor la ON l.isbn = la.isbn
JOIN   autores a    ON la.autor_id = a.autor_id
WHERE  l.titulo = 'Antología del Cuento Colombiano';
JOIN 2 — Listado general ordenado
SELECT
    l.titulo            AS "Título",
    a.nombre            AS "Autor",
    l.anio_publicacion  AS "Año"
FROM   libros l
INNER JOIN libro_autor la ON l.isbn = la.isbn
INNER JOIN autores a    ON la.autor_id = a.autor_id
ORDER BY l.titulo ASC;
⚠ Preparación para el Reto (5 min): Explicar que el Reto agrega 2 tablas más (generos y libro_genero) siguiendo exactamente el mismo patrón. Si entienden este JOIN, el Reto es aplicar lo mismo una vez más.

LEFT JOIN — Registros sin pareja

⏱ 35 min
🎯 Objetivo: El aprendiz distingue INNER JOIN de LEFT JOIN y sabe cuándo usarlo: cuando necesita todos los registros del lado izquierdo, tengan o no coincidencia en la tabla derecha.
📐 Comparación visual INNER vs LEFT
INNER JOIN
  A ∩ B
 ╔═══╗
 ║ A ║▓▓▓║ B ║
 ╚═══╝   ╚═══╝
Solo filas que coinciden
en AMBAS tablas.
LEFT JOIN
  A ∪ (A ∩ B)
 ╔═══╗
 ║▓▓▓║▓▓▓║ B ║
 ╚═══╝   ╚═══╝
TODAS las filas de A;
NULL donde no hay B.
💻 Ejemplos progresivos
1. ¿Qué autores NO tienen libros registrados?
-- LEFT JOIN: incluye autores aunque no tengan libros en libro_autor
SELECT
    a.nombre         AS "Autor",
    l.titulo         AS "Libro"
FROM   autores    a
LEFT JOIN libro_autor la ON a.autor_id = la.autor_id
LEFT JOIN libros     l  ON la.isbn    = l.isbn;
-- Autores sin libros aparecerán con NULL en la columna "Libro"
2. Filtrar SOLO los que no tienen libros (patrón NULL)
SELECT a.nombre AS "Autor sin libros"
FROM   autores    a
LEFT JOIN libro_autor la ON a.autor_id = la.autor_id
WHERE  la.isbn IS NULL;
-- IS NULL filtra únicamente las filas sin coincidencia
3. Libros sin género asignado
SELECT l.titulo AS "Libro sin género"
FROM   libros       l
LEFT JOIN libro_genero lg ON l.isbn = lg.isbn
WHERE  lg.isbn IS NULL;
4. Reporte completo: todos los libros con su género (o "Sin clasificar")
SELECT
    l.titulo                              AS "Título",
    COALESCE(g.nombre_genero, 'Sin clasificar') AS "Género"
FROM   libros       l
LEFT JOIN libro_genero lg ON l.isbn      = lg.isbn
LEFT JOIN generos      g  ON lg.genero_id = g.genero_id
ORDER BY l.titulo ASC;
-- COALESCE devuelve el primer valor no NULL de la lista
💡 Regla de oro: usa INNER JOIN cuando solo te interesan las coincidencias; usa LEFT JOIN cuando necesitas todos los registros de la tabla izquierda aunque no haya pareja. El patrón WHERE lado_derecho IS NULL es la forma clásica de detectar "huérfanos".
Ejercicio (10 min): Pedir a los aprendices que listen todos los géneros con cuántos libros tienen, incluyendo los géneros que aún no tienen ningún libro asignado. Pista: LEFT JOIN desde generos hacia libro_genero + COUNT(lg.isbn).

Vistas (VIEW)

⏱ 35 min
🎯 Objetivo: El aprendiz crea, consulta y elimina vistas; entiende que una vista es una consulta guardada con nombre que se comporta como tabla virtual — sin duplicar datos.
📖 ¿Qué es una vista?
  • Es una consulta SELECT almacenada con un nombre en la BD.
  • No copia datos: cada vez que se consulta, ejecuta el SELECT original.
  • Simplifica consultas complejas, oculta columnas sensibles y centraliza la lógica de negocio.
  • Se consulta igual que una tabla: SELECT * FROM nombre_vista;
💻 Sintaxis y ejemplos
1. Crear una vista básica
-- Vista: catálogo de libros con autor
CREATE VIEW v_catalogo AS
SELECT
    l.isbn,
    l.titulo,
    a.nombre            AS "Autor",
    l.anio_publicacion  AS "Año"
FROM   libros      l
JOIN   libro_autor la ON l.isbn     = la.isbn
JOIN   autores     a  ON la.autor_id = a.autor_id
ORDER BY l.titulo ASC;
2. Usar la vista como si fuera una tabla
-- Consultar la vista directamente
SELECT * FROM v_catalogo;

-- Filtrar sobre la vista
SELECT * FROM v_catalogo
WHERE  "Año" > 1990;
3. Vista con LEFT JOIN: libros y sus géneros
CREATE VIEW v_libros_generos AS
SELECT
    l.titulo,
    COALESCE(g.nombre_genero, 'Sin clasificar') AS genero
FROM   libros       l
LEFT JOIN libro_genero lg ON l.isbn      = lg.isbn
LEFT JOIN generos      g  ON lg.genero_id = g.genero_id;
4. Reemplazar o eliminar una vista
-- Reemplazar sin borrar (PostgreSQL 9.4+)
CREATE OR REPLACE VIEW v_catalogo AS
SELECT isbn, titulo FROM libros;  -- versión simplificada

-- Eliminar la vista
DROP VIEW v_catalogo;
DROP VIEW IF EXISTS v_catalogo;  -- sin error si no existe
⚠ Convención de nombres: prefija siempre las vistas con v_ para distinguirlas de las tablas reales. Es una práctica estándar que facilita el mantenimiento.
Ejercicio (10 min): El aprendiz crea v_autores_colombianos que devuelva nombre y número de libros publicados de los autores cuya nacionalidad sea 'Colombiana'. Combina GROUP BY y COUNT dentro de la vista.

Funciones definidas por el usuario (UDF)

⏱ 40 min
🎯 Objetivo: El aprendiz escribe funciones en PL/pgSQL que encapsulan lógica reutilizable, las invoca desde un SELECT y distingue función (retorna valor) de procedimiento (ejecuta acciones).
📖 Anatomía de una función PL/pgSQL
Estructura base
CREATE OR REPLACE FUNCTION nombre_funcion(param1 tipo, ...)
RETURNS tipo_retorno
LANGUAGE plpgsql
AS $$
DECLARE
    variable tipo;         -- variables locales (opcional)
BEGIN
    -- lógica SQL / PL
    RETURN valor;
END;
$$;
💻 Ejemplos progresivos
1. Función que cuenta libros de un autor
CREATE OR REPLACE FUNCTION contar_libros_autor(p_autor_id INTEGER)
RETURNS INTEGER
LANGUAGE plpgsql
AS $$
DECLARE
    total INTEGER;
BEGIN
    SELECT COUNT(*) INTO total
    FROM   libro_autor
    WHERE  autor_id = p_autor_id;
    RETURN total;
END;
$$;

-- Uso:
SELECT nombre, contar_libros_autor(autor_id) AS "# Libros"
FROM   autores;
2. Función que clasifica un libro por año
CREATE OR REPLACE FUNCTION clasificar_epoca(p_anio INTEGER)
RETURNS VARCHAR
LANGUAGE plpgsql
AS $$
BEGIN
    IF    p_anio < 1900 THEN RETURN 'Clásico';
    ELSIF p_anio < 1970 THEN RETURN 'Moderno temprano';
    ELSIF p_anio < 2000 THEN RETURN 'Moderno';
    ELSE                     RETURN 'Contemporáneo';
    END IF;
END;
$$;

-- Uso:
SELECT titulo,
       anio_publicacion,
       clasificar_epoca(anio_publicacion) AS "Época"
FROM   libros;
3. Función que retorna una tabla (TABLE-VALUED)
CREATE OR REPLACE FUNCTION libros_por_genero(p_genero VARCHAR)
RETURNS TABLE(titulo VARCHAR, anio INTEGER)
LANGUAGE plpgsql
AS $$
BEGIN
    RETURN QUERY
        SELECT l.titulo, l.anio_publicacion
        FROM   libros       l
        JOIN   libro_genero lg ON l.isbn      = lg.isbn
        JOIN   generos      g  ON lg.genero_id = g.genero_id
        WHERE  g.nombre_genero = p_genero
        ORDER BY l.titulo;
END;
$$;

-- Uso:
SELECT * FROM libros_por_genero('Novela');
4. Eliminar una función
DROP FUNCTION IF EXISTS contar_libros_autor(INTEGER);
DROP FUNCTION IF EXISTS clasificar_epoca(INTEGER);
💡 Diferencia clave función vs procedimiento: una FUNCTION siempre retorna un valor y puede usarse dentro de un SELECT; un PROCEDURE ejecuta acciones (INSERT, UPDATE, COMMIT) y se llama con CALL. En PostgreSQL 11+ ambos existen.
Ejercicio (12 min): El aprendiz crea la función titulo_formateado(p_isbn VARCHAR) que devuelva el título en UPPER + el año entre paréntesis. Ejemplo: 'CIEN AÑOS DE SOLEDAD (1967)'. Usa SELECT ... INTO dentro de la función y CONCAT o || para armar el texto.
10

Procedimientos almacenados (PROCEDURE)

⏱ 40 min
🎯 Objetivo: El aprendiz escribe procedimientos que encapsulan operaciones DML completas (con parámetros IN/OUT), maneja errores con EXCEPTION y los invoca con CALL.
📖 Función vs Procedimiento — tabla comparativa
CaracterísticaFUNCTIONPROCEDURE
Retorna valor✅ Siempre (RETURNS tipo)❌ (usa parámetros OUT)
Uso en SELECT✅ SELECT mi_func()❌ Solo CALL mi_proc()
COMMIT / ROLLBACK❌ No puede✅ Puede controlar transacciones
DML (INSERT/UPDATE)✅ (con restricciones)✅ Sin restricciones
Disponible desdePostgreSQL 7+PostgreSQL 11+
💻 Ejemplos
1. Procedimiento: registrar un nuevo libro completo
CREATE OR REPLACE PROCEDURE registrar_libro(
    p_isbn       VARCHAR,
    p_titulo     VARCHAR,
    p_anio       INTEGER,
    p_autor_id   INTEGER
)
LANGUAGE plpgsql
AS $$
BEGIN
    -- Insertar el libro
    INSERT INTO libros (isbn, titulo, anio_publicacion)
    VALUES (p_isbn, p_titulo, p_anio);

    -- Asociar al autor
    INSERT INTO libro_autor (isbn, autor_id)
    VALUES (p_isbn, p_autor_id);

    RAISE NOTICE 'Libro "%" registrado correctamente.', p_titulo;
END;
$$;

-- Invocación:
CALL registrar_libro('978-99', 'La Vorágine', 1924, 1);
2. Procedimiento con manejo de errores (EXCEPTION)
CREATE OR REPLACE PROCEDURE registrar_libro_seguro(
    p_isbn       VARCHAR,
    p_titulo     VARCHAR,
    p_anio       INTEGER,
    p_autor_id   INTEGER
)
LANGUAGE plpgsql
AS $$
BEGIN
    INSERT INTO libros (isbn, titulo, anio_publicacion)
    VALUES (p_isbn, p_titulo, p_anio);

    INSERT INTO libro_autor (isbn, autor_id)
    VALUES (p_isbn, p_autor_id);

EXCEPTION
    WHEN unique_violation THEN
        RAISE NOTICE 'Error: el ISBN % ya existe.', p_isbn;
    WHEN foreign_key_violation THEN
        RAISE NOTICE 'Error: autor_id % no existe.', p_autor_id;
    WHEN OTHERS THEN
        RAISE NOTICE 'Error inesperado: %', SQLERRM;
END;
$$;
3. Procedimiento con parámetro OUT
CREATE OR REPLACE PROCEDURE obtener_total_libros(
    OUT p_total INTEGER
)
LANGUAGE plpgsql
AS $$
BEGIN
    SELECT COUNT(*) INTO p_total FROM libros;
END;
$$;

-- Invocación con variable de resultado:
DO $$
DECLARE v_total INTEGER;
BEGIN
    CALL obtener_total_libros(v_total);
    RAISE NOTICE 'Total de libros: %', v_total;
END;
$$;
⚠ Importante: Los procedimientos almacenados se guardan compilados en la BD — si cambias una tabla referenciada (renombras una columna, por ejemplo) el procedimiento no falla al crearlo sino al ejecutarse. Usa DROP PROCEDURE IF EXISTS nombre(tipos); antes de recrear.
Ejercicio (15 min): Crear el procedimiento asignar_genero(p_isbn VARCHAR, p_genero_id INTEGER) que inserte una fila en libro_genero con manejo de error para el caso en que esa combinación ya exista (unique_violation). Invocar con CALL y verificar en pgAdmin.

Triggers (Disparadores)

⏱ 45 min
🎯 Objetivo: El aprendiz entiende el ciclo BEFORE/AFTER, crea una función trigger y la asocia a una tabla para automatizar auditoría y validaciones sin intervención del cliente.
📐 Anatomía de un trigger en PostgreSQL
  Evento DML                Función trigger             Tabla objetivo
  ─────────────             ──────────────────          ───────────────
  INSERT / UPDATE           CREATE FUNCTION f()         libros
  DELETE / TRUNCATE  ────►  RETURNS trigger        ────► (NEW, OLD)
                            LANGUAGE plpgsql
                            AS $$ ... $$;

  BEFORE  ──► puede modificar NEW o cancelar con RAISE EXCEPTION
  AFTER   ──► registra el cambio ya confirmado (auditoría)
💻 Caso 1 — Auditoría automática de cambios
1a. Tabla de auditoría
CREATE TABLE auditoria_libros (
    audit_id   SERIAL      PRIMARY KEY,
    isbn       VARCHAR(20),
    operacion  VARCHAR(10),  -- 'INSERT', 'UPDATE', 'DELETE'
    titulo_ant VARCHAR(200),
    titulo_nvo VARCHAR(200),
    fecha_hora TIMESTAMP DEFAULT NOW()
);
1b. Función trigger de auditoría
CREATE OR REPLACE FUNCTION fn_auditar_libros()
RETURNS TRIGGER
LANGUAGE plpgsql
AS $$
BEGIN
    IF (TG_OP = 'INSERT') THEN
        INSERT INTO auditoria_libros(isbn, operacion, titulo_nvo)
        VALUES (NEW.isbn, 'INSERT', NEW.titulo);

    ELSIF (TG_OP = 'UPDATE') THEN
        INSERT INTO auditoria_libros(isbn, operacion, titulo_ant, titulo_nvo)
        VALUES (NEW.isbn, 'UPDATE', OLD.titulo, NEW.titulo);

    ELSIF (TG_OP = 'DELETE') THEN
        INSERT INTO auditoria_libros(isbn, operacion, titulo_ant)
        VALUES (OLD.isbn, 'DELETE', OLD.titulo);
    END IF;
    RETURN NEW;
END;
$$;
1c. Asociar el trigger a la tabla libros
CREATE TRIGGER tg_auditar_libros
AFTER INSERT OR UPDATE OR DELETE
ON libros
FOR EACH ROW
EXECUTE FUNCTION fn_auditar_libros();

-- Probar: cualquier INSERT/UPDATE/DELETE en libros queda registrado
UPDATE libros SET titulo = 'Cien Años de Soledad' WHERE isbn = '978-01';
SELECT * FROM auditoria_libros;
💻 Caso 2 — Validación BEFORE INSERT
Impedir años de publicación futuros
CREATE OR REPLACE FUNCTION fn_validar_anio()
RETURNS TRIGGER
LANGUAGE plpgsql
AS $$
BEGIN
    IF NEW.anio_publicacion > EXTRACT(YEAR FROM NOW()) THEN
        RAISE EXCEPTION
            'Año de publicación % no puede ser futuro.',
            NEW.anio_publicacion;
    END IF;
    RETURN NEW;  -- devolver NEW confirma la operación
END;
$$;

CREATE TRIGGER tg_validar_anio
BEFORE INSERT OR UPDATE
ON libros
FOR EACH ROW
EXECUTE FUNCTION fn_validar_anio();

-- Prueba: esto debe fallar
INSERT INTO libros(isbn, titulo, anio_publicacion)
VALUES('978-XX', 'Libro del futuro', 2099);
🔧 Gestión de triggers
Listar, deshabilitar y eliminar
-- Ver todos los triggers de la BD actual
SELECT trigger_name, event_manipulation, event_object_table, action_timing
FROM   information_schema.triggers
ORDER BY event_object_table;

-- Deshabilitar temporalmente
ALTER TABLE libros DISABLE TRIGGER tg_auditar_libros;

-- Volver a habilitar
ALTER TABLE libros ENABLE TRIGGER tg_auditar_libros;

-- Eliminar definitivamente
DROP TRIGGER IF EXISTS tg_auditar_libros ON libros;
DROP FUNCTION IF EXISTS fn_auditar_libros();
⚠
Variables especiales en triggers:
NEW — fila nueva (INSERT / UPDATE). Modificable en BEFORE.
OLD — fila anterior (UPDATE / DELETE). Solo lectura.
TG_OP — texto con la operación: 'INSERT', 'UPDATE', 'DELETE'.
TG_TABLE_NAME — nombre de la tabla que disparó el trigger.
Devolver NULL en un trigger BEFORE cancela la operación DML.
Ejercicio (15 min): El aprendiz crea un trigger BEFORE INSERT sobre autores que convierta automáticamente el campo nombre a UPPER(nombre) antes de guardar — así todos los autores quedan en mayúsculas sin importar cómo se ingresaron. Verificar con un INSERT en minúsculas.
